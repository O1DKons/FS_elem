# FS_elem v0.2.1 — Windows 10/11 x64

Кандидат содержит исходники запуска, платформенные замки и закреплённую Windows-сборку FFmpeg. Они готовы для нативной проверки, но успешная установка, запуск и анализ на Windows пока не подтверждены. Значение ready в исходной конфигурации разрешает установку закреплённых файлов; оно не означает пройденную проверку Windows. Это комплект исходников и готового интерфейса, а не автономный EXE. [Статус v0.2.1](v0.2.1.md).

Для подготовленного выпуска нужны Node.js 24 с npm, Python 3.12 для science и Python 3.9 для pose. Используется CPU; GPU, CUDA и CoreML не требуются. Windows ARM64 и WSL не входят в этот профиль.

Для проверки кандидата распакуйте полный архив в собственный каталог. В PowerShell перейдите в его корень. Если Python устанавливается через uv:

```powershell
uv python install 3.12.12 3.9.25
$sciencePython = uv python find 3.12.12
$posePython = uv python find 3.9.25
npm.cmd run setup:release -- --science-python "$sciencePython" --pose-python "$posePython"
```

Можно передать пути к уже установленным нативным 64-битным Python нужных версий. Две среды создаются только внутри `.runtime`; Windows-замки используют `--require-hashes` и готовые wheels. Модели и FFmpeg устанавливаются из закреплённых источников. Установка требует сети при первом запуске. Собранный интерфейс сохраняется; его пересборка — отдельная команда `npm.cmd run build` для разработки.

Для запуска откройте `FS_elem.cmd` либо выполните:

```powershell
npm.cmd run start:release -- --open
```

Браузер откроется после готовности UI и API. По умолчанию адрес — `http://127.0.0.1:5174/analysis`. Для остановки используйте Ctrl+C. Параметры лаунчера сохраняются; при запуске через cmd пути с пробелами или `&` заключайте в кавычки. Менять PowerShell ExecutionPolicy не требуется: используйте `npm.cmd`.

При несовпадении платформы, замка или маркера настройка сохраняет существующую среду и сообщает причину. Для принятой старой Mac-среды предусмотрена проверяемая миграция маркера через повторную `setup:release`; копировать Mac-venv на Windows нельзя. Не удаляйте пользовательские видео и сохранённые результаты при восстановлении зависимостей.

Нативная CI-проверка объявлена для Windows Server 2022 x64 на ветке release/v0.2.1: первая установка, фактические FFmpeg -version/-L, десять проверок владения процессами и production HTTP-запуск/остановка/повторный запуск. Пока это подготовленные исходники, а не выполненный CI. Серверный CI не подтверждает запуск двойным щелчком на Windows 10/11. Автоматический CI не отправляет реальное видео на анализ и не запускает нейросеть; этот этап требует отдельной ограниченной проверки после установки и жизненного цикла. Готовность выпуска требует отдельной проверки установки, загрузки исходного видео, CPU-анализа, просмотра результата, отмены и повторного запуска. Точность распознавания и физические обороты этим переносом не подтверждаются.
